# 公网视频直链适配设计

## 目标

在现有多平台批量下载工具中支持所有可匿名访问的公网 HTTP/HTTPS 视频直链。完成标准是用户提供的 `bdstatic.com` MP4 链接能够创建任务、下载到指定目录，且成品存在可读取的视频流。

微信视频号不在本次范围内。

## 实现方案

新增边界明确的公网视频直链适配器，并继续禁用 yt-dlp `GenericIE`。适配器先安全探测媒体响应，再把结果转换为现有统一下载信息，从而复用队列、暂停、重试、续传、进度和文件命名逻辑。

## 链接识别与安全

- 输入允许 HTTP 和 HTTPS。
- 每次请求和跳转前解析域名并检查目标 IP，拒绝环回、局域网、链路本地、保留地址、无效端口和非 HTTP(S) 协议。
- 普通平台网页继续要求 HTTPS；HTTP 只在最终目标经探测确认是视频直链时接受。
- 直链验证优先 HEAD；服务器不支持 HEAD 或未返回可判断的类型时，使用带 `Range: bytes=0-4095` 的 GET。
- 最终响应必须是 `video/*`。不能仅凭扩展名判定成功。
- 最多允许五次跳转，不向日志写入带临时签名的完整媒体地址。

## 数据流

新增 `DirectMediaIE`：

1. 安全探测原始 URL 和每次跳转。
2. 获取最终 URL、内容类型、内容长度和响应文件名。
3. 使用规范化最终 URL 的 SHA-256 前 16 位作为稳定视频 ID。
4. 标题依次取 `Content-Disposition` 文件名、URL 路径文件名、`视频直链_<ID>`。
5. 输出 yt-dlp 可消费的单格式视频信息。

平台标识为 `direct`，界面标签显示“视频直链”。批次创建时，已匹配专用平台解析器的 HTTPS 链接沿用原流程；其余 HTTP/HTTPS 候选交给直链适配器联网确认。去重仍使用 `(platform, video_id)`。

## 测试与验收

自动化测试覆盖 HTTP/HTTPS 输入、HEAD 成功、Range GET 回退、逐跳安全校验、私网拒绝、非视频拒绝、稳定 ID、文件名、批次创建、下载器注册和界面标签。现有抖音、快手、B 站测试必须保持通过。

真实验收使用：

`http://vd3.bdstatic.com/mda-sehd0u71rk974i1y/360p/h264/1779095503307490225/mda-sehd0u71rk974i1y.mp4`

链接需创建任务并下载到临时目录。验收检查任务完成、文件非空，并用 FFmpeg/ffprobe 确认至少存在一条视频流。完成后重启源码版桌面程序；本次不重新生成安装包或 EXE。
