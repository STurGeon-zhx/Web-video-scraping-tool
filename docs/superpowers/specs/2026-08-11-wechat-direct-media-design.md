# 微信视频号与公网视频直链适配设计

## 目标

在现有多平台批量下载工具中增加两类输入：

- 微信视频号公开预览链接，例如 `https://channels.weixin.qq.com/finder-preview/pages/sph?id=AcXW41vPJ0`。
- 所有可匿名访问的公网 HTTP/HTTPS 视频直链，例如以 `video/mp4` 响应的 MP4 地址。

完成标准是用户提供的两条链接均能创建任务、下载到指定目录，且成品可正常读取视频流。本次只处理无需登录即可访问的公开内容，不读取微信或浏览器登录资料。

## 方案选择

采用两个边界明确的专用适配器，并继续禁用 yt-dlp `GenericIE`。

- 视频号适配器使用全新匿名会话调用公开预览页自身使用的 `feed/get_feed_info` 接口，解析标题、视频 ID、作者和公开视频地址。
- 直链适配器通过响应头及有限范围 GET 验证目标确实是视频，再将媒体信息转换为现有统一下载信息。

不采用 Playwright 网络拦截，因为它增加浏览器运行时依赖且更容易受页面渲染变化影响。不启用通用网页解析器，因为它会扩大任意网页和 SSRF 攻击面。

## 链接识别与安全

- 视频号只匹配 `channels.weixin.qq.com/finder-preview/pages/sph`，并要求存在非空 `id` 参数。
- 直链允许 HTTP 和 HTTPS，但必须通过实际响应确认是视频；不能仅凭扩展名判定成功。
- 每次请求和跳转前都解析域名并检查目标 IP，拒绝环回、局域网、链路本地、保留地址、无效端口和非 HTTP(S) 协议。
- 视频号页面及其公开接口继续要求 HTTPS。
- 直链验证优先 HEAD；服务器不支持 HEAD 或未返回可判断的类型时，使用带 Range 的小范围 GET。最终响应需为 `video/*`，或同时具备受支持视频扩展名和可接受的二进制媒体响应。
- 跳转次数沿用现有上限，不向日志写入带临时签名的完整媒体地址。

## 组件与数据流

### 视频号适配器

新增独立模块负责：

1. 从预览 URL 提取短标识。
2. 建立全新匿名 `curl-cffi` 会话并获取公开接口所需的初始化信息。
3. 请求公开视频详情，拒绝登录可见、已删除、图集和无视频资源的响应。
4. 优先选择可公开下载的最高质量视频格式，并输出统一的 `id`、`title`、`webpage_url`、`formats` 和请求头。

平台标识为 `wechat_channels`，界面标签显示“视频号”。

### 公网直链适配器

新增独立模块负责安全探测、媒体类型判断和统一信息生成。视频 ID 使用规范化最终 URL 的稳定摘要，标题按以下顺序确定：

1. `Content-Disposition` 中的安全文件名。
2. URL 路径中的文件名。
3. `视频直链_<摘要>`。

平台标识为 `direct`，界面标签显示“视频直链”。下载阶段复用现有 yt-dlp 进度钩子、`.part` 续传、暂停、重试、磁盘检查和安全文件名逻辑。

### 批次与界面

- 快速预览继续只统计候选 URL。
- 创建批次时联网完成最终支持性确认和展开。
- 去重仍使用 `(platform, video_id)`。
- 平台统计及任务列表增加“视频号”和“视频直链”标签。
- 明确提示：视频号链接无效、视频号内容需要登录、视频号无公开视频、直链不是视频、直链目标不安全、网络错误。

## 测试与验收

自动化测试覆盖：

- 视频号 URL 匹配、ID 提取、公开接口响应解析、无视频和登录限制错误。
- HTTP/HTTPS 直链、HEAD 回退 Range GET、重定向逐跳校验、私网拒绝、非视频响应拒绝、标题和稳定 ID。
- 平台识别、批次创建、跨平台去重、下载器注册、错误映射及界面平台标签。
- 现有抖音、快手、B 站测试保持通过。

真实验收使用用户提供且已授权的链接：

- `https://channels.weixin.qq.com/finder-preview/pages/sph?id=AcXW41vPJ0`
- `http://vd3.bdstatic.com/mda-sehd0u71rk974i1y/360p/h264/1779095503307490225/mda-sehd0u71rk974i1y.mp4`

两条链接分别创建独立临时批次并下载到临时目录。验收检查任务完成状态、输出文件非空，并用 FFmpeg/ffprobe 确认至少存在一条可读取的视频流。完成后重启源码版桌面程序；本次不重新生成安装包或 EXE。
